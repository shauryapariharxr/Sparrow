Why Sparrow

Built like a product,
not a port-forward.

Every request is authenticated, rate-limited and scoped to your database. The engine underneath is a hand-built Redis clone — strings, lists, sets, sorted sets, hashes, TTL, pub/sub and persistence.

⌁

Zero latency to first byte

REST with a fast hash-lookup token cache. No TCP handshake, no RESP negotiation — a cold serverless function still lands its first SET in one round trip.

⟐

One API, any runtime

Node, Bun, Deno, Cloudflare Workers, Python, Go, curl. If it can send an HTTPS request with a bearer token, it can talk to your data.

◫

Pipelining built in

Batch up to 1,000 commands in one request. Round trips are the enemy of serverless — kill them with a single array body.

⛨

Airtight tenant isolation

Tokens are derived at auth time, never from request data. Your namespace is resolved before a byte of your command is parsed.

◷

TTL & persistence

Lazy + active expiry like real Redis. Write-ahead log with fsync, atomic snapshots, and exact replay across restarts.

≋

Pub/sub over SSE

Subscribe with a plain GET and an EventSource. Same-tenant channels, heartbeat keep-alives, no websocket infra to run.

Quickstart

From zero to data in three calls.

1

Create a database

Sign up and click Create database in the console.

2

Mint a token

Tokens look like sparrow_…, are shown once, and can be read-only.

3

Call commands

Path style for curl, JSON arrays for code — both hit the same engine.

curl
# set
curl -X POST https://your-host/set/greeting/hello \
  -H "Authorization: Bearer sparrow_…"

# get
curl -X POST https://your-host/get/greeting \
  -H "Authorization: Bearer sparrow_…"
# → {"result":"hello"}
any runtime
const r = await fetch("https://your-host", {
  method: "POST",
  headers: {
    Authorization: "Bearer sparrow_…",
    "Content-Type": "application/json",
  },
  body: JSON.stringify(["SET", "user:42", "ηma"]),
});
const { result } = await r.json();
